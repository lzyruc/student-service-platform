## 代表性bad case与定位

N02“最近一个有成绩的学期，哪些课程需要重点关注？请区分未通过和低分。”主基线两次均失败，补采再次两次失败。四次结果一致不等于普遍失败率，只能说明这组题/数据/模型配置下稳定复现。

真实Tool结果包含：操作系统58分、UNRESOLVED；计算机网络65分、LOW_NUMERIC_SCORE；当前学期加权GPA=0.9；上一学期变化量=-2.25、方向DOWN。

补采模型原文正确写出课程及分数，并表述“GPA下降2.25”。当前 `AcademicAnswerGrounding` 抽取到正数2.25，只允许DTO中的0.9与-2.25，因此将整段回答替换为：

> 本次未采用未经当前数据核实的GPA描述。请以本次成绩数据卡片为准；对话中的自述不能作为成绩或风险结论。

最终HTTP200、Agent=COMPLETED且工具调用正确，但学生需要的课程信息已丢失，所以任务仍失败。M01首轮和追问末轮也被该保护分支替换；这批没有保存它的模型原文，不能进一步臆断具体触发措辞。

证据见 [bad_cases.json](./bad_cases.json)、[补采原始记录](./results/20261106-204637-badcase_capture-c2ec8/observations.jsonl)；`AcademicEvaluationEvidenceTest.characterizesVerifiedDownwardDeltaMagnitudeBeingRejected` 用原Java方法离线验证“下降2.25”被替换而“变化量为-2.25”保留。这个测试是当前缺陷的行为记录，不是修复。

## 最值得实施的下一步：修正GPA变化量的方向归一化

只建议先改 `AcademicAnswerGrounding` 的变化量识别与匹配，并补针对性测试：把“下降2.25”按语义归一化为-2.25，再和本轮DTO的变化量/方向核对；区分GPA水平与GPA变化，不能简单对所有数字取绝对值。仍要拒绝错误的“上升2.25”、历史伪造GPA和没有本轮证据的数字。

范围：该校验类、相关单测及相同任务重跑；不改模型框架、数据库或缓存。验证目标：N02/M01恢复课程答案，原安全/错误数值回归继续通过，再用同一任务/fixture/模型配置比较实际结果。当前没有优化后数据，也不承诺提升百分比。本轮没有实施这项修改。
