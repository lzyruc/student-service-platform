# RAG 检索基准报告（2026-09-27）

## 结论

当前 RAG 在本项目的 16 道固定政策问题上，前 4 个文本块均命中了正确来源文件，其中 15 道完整覆盖人工标注的关键证据。主要问题集中在校历 OCR、文档类型识别、跨类型文本混入和重复文本块。

本报告只记录优化前基线，没有修改 `AIAnalysis.py` 的切块、检索、排序或提示词逻辑。后续优化必须继续使用同一份 `cases.json`，才能计算可比较的提升比例。

## 指标定义

| 指标 | 含义 |
| --- | --- |
| Correct Source Hit@4 | 前 4 个文本块中是否至少有一个来自正确文件 |
| Full Evidence Hit@4 | 前 4 个文本块是否覆盖该题全部必需事实 |
| Mean Evidence Coverage@4 | 每道题已覆盖必需事实的平均比例 |
| Source MRR@4 | 正确来源第一次出现位置的倒数均值，1.0 表示都排在第一位 |
| Expected Type Precision@4 | 前 4 个文本块中属于预期文档类型的平均比例 |

证据匹配前会删除 PDF 抽取产生的空白字符。例如 `开学后 14 天内` 与 `开学后14天内` 视为相同，但不会进行语义推测。

## 逐项发现

### 已达到的效果

1. 16 道题都能在前 4 个结果中找到正确来源文件。
2. 本科生休学、复学、转学，研究生转专业、休学、退学、申诉，以及考试作弊和处分申诉等文字型政策问题，关键证据均被完整召回。
3. 正确来源在所有问题中都排在第 1 位，说明当前 BGE 向量检索对这组明确政策问题有效。

### 暴露的问题

1. **秋季考试周证据缺失**：系统命中了校历图片，但最终上下文没有完整覆盖 `2025年12月29日至2026年1月9日`，该题证据覆盖率为 0%。
2. **校历类型识别错误**：校历文件名为 `微信图片_20260427155528.png`，不包含“校历”，因此 `_infer_doc_type()` 把它标为“通用”。两个校历问题的类型精度均为 0%。
3. **存在跨类型文本混入**：本科生复学、本科生转学的前 4 个结果中各混入 1 个研究生文本块；处分期休学问题混入 1 个本科文本块。
4. **存在重复上下文**：相邻页面合并后继续切块，部分研究生问题的前 4 个结果出现相同页码范围的多个文本块，会消耗上下文空间。
5. **测试范围有限**：当前数据集是依据现有四份资料构建的16道明确事实题，不能代表所有口语化、歧义、多跳或资料缺失问题。

## 复现方式

先确保 `python-services/chroma_db` 已由当前版本构建，然后执行：

```powershell
cd python-services
.\.venv\Scripts\python.exe .\evaluation\rag_eval.py `
  --label baseline_retrieval_2026-09-27 `
  --output .\evaluation\results\baseline_retrieval_2026-09-27.json
```

该命令只运行本地检索，不调用 DeepSeek。

脚本也支持 `--with-answers` 测试完整回答链路，但该模式会把问题和召回的政策片段发送给配置的外部模型服务。本次报告没有执行该模式，因此没有把生成质量或网络延迟纳入基线数字。

## 后续对比规则

RAG 优化完成后，使用相同的 `cases.json` 生成新结果。提升按百分点计算：

```text
提升（百分点） = 优化后指标 × 100 - 基线指标 × 100
```

例如 Full Evidence Hit@4 从 93.75% 提升到 100.00%，应记录为“提升 6.25 个百分点”，而不是笼统写成“提升很多”。如果增加新测试题，应同时保留这16题的固定子集结果，避免测试集变化造成虚假提升。
